# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `audit`: replays the Stop gate over your local Claude Code transcripts and counts, per project folder, how many edit turns ended with a passing check (`verified`), with checks that did not pass after the last edit, or with no check, plus subagent calls and how many next prompts carry the gate's weak breakage cue. Local only: no key, no Jev call, nothing sent, no message text kept; folders are 12-hex hashes unless `--names`; the full table goes to a file in the results folder. On the maintainer's machine 63 of 286 edit turns were verified. `audit --ask --project <text>` (opt-in, at most 300 turns, `--dry-run` first, `--skip <file>` for private terms) reads the turns with Jev: the Stop gate's four questions on unverified turns and a new generic-pack question, `audit.pushback`, on the user's next prompt, then compares the gate's `would_block` with the pushback (one-sided Fisher exact test, AUROC, a registered power rule that returns `not_evaluable` below 15 and 15). It also prints the gate `funnel` (unverified, claimed done, not verified, a check applies, would block) and `audit` prints the verified share by ISO week. Record: [audit-command.md](docs/decisions/audit-command.md).

- `audit --compare <ISO date>` (with `--until` and `--exclude <text>`): splits your edit turns at a date and compares the share that ended with a passing check before and after it, pooled and over the folders that have at least 3 edit turns in both windows, with a one-sided Fisher exact test. Verdict `not_evaluable` (under 30 edit turns in a window), `higher`, `lower` or `no_signal`; an association after a date, not an effect. Local only, one scan of the transcripts, counts and folder hashes only. The bars were registered before the first run in [audit-command.md](docs/decisions/audit-command.md); the build was chosen with Jev at 0.77, below the 0.90 bar, as the cheaper and reversible option (the option costs were written by the assistant).

- `scripts/verify-release.mjs <version>`: after an npm publish, checks the registry tarball's sha512 against the integrity value the registry reports and compares every file in it byte for byte with the git tag's `npm/` folder (`--out <dir>` keeps the verified tarball for the GitHub release asset). Read-only; run against the real 0.2.7 package it found 17 of 17 files identical. It replaces the by-hand comparison noted in each release row.

- `scripts/check-ui-firefox.mjs <light|dark>` (maintainer tool, not shipped): starts the real `ui` server on synthetic data and drives headless Firefox over WebDriver BiDi, with no driver or dependency; 22 checks (tabs, labelling by key and click, excerpts shown as text, exports, 375 px, dark mode, console and CSP errors). Firefox 147.0.2 passed 22 of 22 in light and dark; a page that set an excerpt through `innerHTML` failed three of them. Firefox logs one console error for `/favicon.ico` because the CSP says `img-src 'none'`; it is counted, not failed, and the policy is unchanged. Record: [ui-second-engine.md](docs/decisions/ui-second-engine.md).

- `done`: reads the one-line JSON summaries that Pint, PHPStan and Rector print in agent format (`{"tool":"pint","result":"passed"}`, `{"tool":"phpstan","result":"failed","errors":2,...}`, `{"tool":"rector","result":...,"totals":{...}}`) as runner facts: counts and fixed sentences only, never paths or messages; `fixed` (files rewritten) counts as an incomplete run. In real projects since 2026-10-09, PHP-stack `done` calls got 1 `met` of 13 (other stacks 15 of 21), because these lines were unread. A replay over 117 local outputs moved 47 from exit-code-only to parsed, and read all 9 with a `failed` object as failing; the effect on real calls is not measured yet. Record: [php-agent-json.md](docs/decisions/php-agent-json.md).

### Changed

- `scripts/usage-report.mjs` has `--exclude-pack <name>` (leaves out every session that wrote a receipt under that pack, counted as `excluded_by_pack`) and `--until <ISO time>`. One reply-gate session wrote 265 of 268 non-clear `decide` re-asks since the briefing went live, so the old re-ask baseline did not measure coding use; the baselines are recomputed under the same rules in [usage-report.md](docs/decisions/usage-report.md).
- The CI size tripwire for `dist/cli.mjs` moved from 400000 to 450000 bytes: the bundle was 379,415 bytes before `audit` and 400,953 after it (about 21,500 bytes, the command, its study code and its `--describe` strings). The `hook.mjs` tripwire (200000; 168,984 bytes) is unchanged and does not include the audit code. Chosen with Jev (`decide` p 0.99, both orders agree; the option costs were written by the assistant).
- Weekly docs watch: `llms.txt` is now recorded with its sorted link paths next to the count, so a change prints the added and removed pages (a swap that keeps the count included); a snapshot that holds only the count still compares by hash until the next `--update`. Record: [docs-watch-link-paths.md](docs/decisions/docs-watch-link-paths.md).

## [0.2.8] - 2026-10-11

`done` now reads several kinds of log that used to count as exit-code-only (echoed check commands, silent eslint and oxlint runs, Vite builds with only the `built in` line), `lint-pack` warns on two more wording traps, and two Windows defects are fixed. The new `done` readings are checked on invented suites and on replays of real logs; their wrong `met` rate on real use is not labelled yet. Echoed command lines, arguments included, can now be sent to Jev in exit-code-only runs ([privacy](docs/privacy.md)).

### Added

- CI: a `windows` job (Node 24: typecheck and tests). It started as informational (`continue-on-error`) to list what breaks on Windows; after the fixes below it is green and enforced like the macOS and Ubuntu jobs. The README says the unit tests run on Windows and that the key step and a real Windows session are not tested. Record: [windows-ci-informational.md](docs/decisions/windows-ci-informational.md).
- `scripts/usage-report.mjs` (maintainer tool, not shipped): the four usage measures from the local data directory as one JSON line of counts (edit turns that end with a counted check, re-asks after a non-clear `decide` that became clear, exit-code-only share of `missing` with evidence size, labels by verdict), with `--days`, `--since` and `--data-dir` and `--exclude-session <id|current>` (repeatable) to leave out the receipts and stops of your own development session. Record: [usage-report.md](docs/decisions/usage-report.md).

### Changed

- `lint-pack`: two new warnings from TypeSafe's jaggedness page, `negated_true` (a Noul whose `true` criterion starts with no, not, never or none) and `numeric_value` (a hex colour, `rgb(` call or `0x` literal in a question). The shipped packs stay clean. Record: [lint-pack-jaggedness.md](docs/decisions/lint-pack-jaggedness.md).
- `done`: for exit-code-only evidence, up to three echoed command lines (`$ cmd`, `> cmd`; 80 characters each) are now sent as `command_lines` when the command's first word is a known check tool, and none when the echoed command hides, redirects or tolerates its output or failure (`--quiet`, `|| true`, `> file`, ...). Before, `$ tsc --noEmit` then `exit code: 0` read `missing` (0.2) for "typecheck passes" because Jev could not tell what ran. Re-recorded on the done suites: wrong `met` stays 0 everywhere, recall done-v2 0.77 to 0.83 and hold-out 4 0.61 to 0.71. Privacy: those command lines (arguments included) now leave the machine in such runs; `docs/privacy.md` says so. The recorded answers of the done and injection suites were replaced by the re-recorded ones. Record: [command-echo-facts.md](docs/decisions/command-echo-facts.md).
- `done`: a clean run of `eslint` or `oxlint` that prints nothing is now read as a clean run (facts: errors 0, warnings 0, "printed no diagnostics and exited 0", build-only) when the log is exactly one npm script echo (`> pkg@ver script`, `> eslint ...`), a blank line and exit lines of 0. Flags that hide, redirect or change output (`--quiet`, `-q`, `--silent`, `--format`/`-f`, `--output-file`/`-o`, `--fix`, `no-error` flags), shell operators (`|| true`, `;`, `&&`, `>`, `|`), any other output line, a second script and a non-zero or missing exit stay on the exit-code reading. The 357 recorded `done` cases keep their facts; a new recorded suite `done-silent` (15 invented cases from real shapes) has 0 wrong `met` and `met` on 5 of 5 clean forms; on 38 real lint outputs, 11 more are parsed. Record: [silent-success-reading.md](docs/decisions/silent-success-reading.md).
- `done`: a Vite build log without the `vite v5.x building` banner is read as a Vite build when it has the whole-line `✓ built in <time>`, with or without a size table (a real Vite 8 log had none and read as exit-code-only, `missing` 0.49 for an exit-status criterion); `[PLUGIN_TIMINGS] Warning:` blocks count as one warning, so a "no warnings" criterion on that shape is not `met`; with the banner nothing changes. The parsed facts of the 357 recorded `done` cases are identical; on 38 real build outputs, 2 more are parsed (the other 18 exit-code-only logs are silent `nest build` runs). Record: [vite-built-line.md](docs/decisions/vite-built-line.md).

### Fixed

- Circuit breaker on Windows: the failure count is written by temp file and rename, and Windows refuses a rename onto a file another process has open (a parallel session's stale scan reads every entry); the rename is now retried a few times with short waits, and the temp file is removed if it still fails. Found by the Windows CI job, where one of 16 parallel sessions lost its count.
- Stop gate records on Windows: pruning of `stops.jsonl` (records older than 90 days, past 2 MB) never ran there, because Windows refuses to replace a file that this process still holds open. The descriptor is now closed before the replace on Windows, and the post-replace copy of lines another session appended in that instant is skipped there. The two tests of an append that lands on a file being renamed away run on POSIX only. The tests that build workers by absolute path now import them by file URL, the CLI path in the abort test comes from a file URL, and several tests no longer assume POSIX paths, a POSIX shell for their fixtures or a bare environment without `SystemRoot`.
- Checkout class on Windows: a plain main checkout opened from a subfolder was read as `linked` when the temp or home path has an 8.3 short name (`RUNNER~1`), because the two git paths were compared without expanding short names. They are now resolved with the native real path. Found by the informational Windows CI job.

## [0.2.7] - 2026-10-09

The `done` and `decide` next steps now say what to do instead of repeating that the evidence was not enough, the session briefing lists the checks it finds in the project and asks for them after edits, and wrong `met` verdicts can be labelled from a queue. No verdict, `p`, reason or threshold changed.

### Fixed

- SessionStart briefing: a broken symlink in the project root no longer hides the one subdirectory whose checks the briefing would list; before, one dangling entry silently turned the detection off.

### Added

- `receipts --evidence-queue [--verdict <v>]`: up to 20 newest `done` receipts that have stored evidence (`REFEREE_KEEP_EVIDENCE=1`) and no label, with id, time, verdict, p, trust and runner names only, so labelling a wrong `met` is `--evidence-queue --verdict met`, `--show-evidence <id>`, `--label-receipt <id> --right|--wrong`. No criteria or evidence text is printed by the queue. Record: [evidence-queue.md](docs/decisions/evidence-queue.md).
- SessionStart briefing (generic pack): one line after the `done` pipe example, "After editing files, run the checks below this way before saying it is done." The detected-checks list is capped at 80 joined characters (was 90) and the briefing stays within 700 characters in tests (was 600); it measures 660 on a real project and 697 in the long-plugin-path test, the hard cap stays 800. It is observational: the report is the share of edit turns that end with a counted check, 28 of 52 before. Record: [briefing-done-nudge.md](docs/decisions/briefing-done-nudge.md).
- Weekly docs watch: TypeSafe's "Jev 1.13 jaggedness" page (its known weaknesses and "last reviewed" date) joins `models.md`, `api.md` and `llms.txt` as a watched page, and the newest versions of the Python and JavaScript SDK changelogs are recorded and printed as `::notice::` lines when they change; those notices never fail the run. Record: [docs-watch-jaggedness.md](docs/decisions/docs-watch-jaggedness.md).

### Changed

- SessionStart briefing: when no manifest is found from the working directory up to the project root, and exactly one immediate subdirectory of the root has detected checks, they are listed as `cd <dir> && <command>`. With none or several the old text stays, so the briefing never picks between subprojects. On the owner's 14 project roots this moves the count with checks from 8 to 10 (aggregate). Record: [detected-checks-one-subdir.md](docs/decisions/detected-checks-one-subdir.md).
- `decide`: the `next_step` of a `weak` or `tie` result now names the lean and the runner-up and says what kind of fact separates them (what each costs or breaks, how easily it is undone). In local receipts (aggregate counts), a re-ask within 10 minutes of a non-clear decide was `clear` in 24 of 83 cases, in chains up to 14 long; the old text said "add the missing fact" without saying which. Verdict, lean and probabilities do not change; the output stays under 400 characters. Record: [decide-weak-next-step.md](docs/decisions/decide-weak-next-step.md).
- Errors: a `credential_in_state` stop in a multi-line field now names the line of the first match (`secret_assignment in evidence, line 2`) and, for `secret_assignment`, says what the rule matches (a name with key, token, secret or password next to a long mixed-character value); the value is never printed and nothing stops less than before. `too_large` for a decide context or a claims source now says the estimated tokens and the limit, and decide names the largest context file. Record: [stop-error-hints.md](docs/decisions/stop-error-hints.md).
- `done`: a `missing` answer on evidence that held only an exit code line (`trust: exit_code`) now says so in `next_step` and shows how to pipe the check's output in front of the exit code line, instead of the generic "same evidence gives the same answer". Verdict, `p` and `reason` do not change. The same `next_step` tells a tool that prints nothing when it passes (eslint, tsc) to be asked with a criterion worded as its exit status (record: [exit-only-silent-tools.md](docs/decisions/exit-only-silent-tools.md)). Every `done` result and receipt outcome also carries `evidence_lines`, a count of the evidence's lines, so tiny evidence (output never piped) can be told from a large log no parser reads. Record: [exit-only-evidence.md](docs/decisions/exit-only-evidence.md).
- SessionStart briefing: when no area lists checks, it names up to 4 checks detected from the nearest `package.json`, `composer.json` (or `artisan`), `Cargo.toml` or `go.mod` and marks them `(detected)`, instead of always saying `none listed in .claude/referee.json`. Only script names are read, never script bodies; a missing or unparsable manifest keeps the old text, and explicit `areas` checks are untouched. On the owner's 14 project roots, 8 yield at least one detected check (aggregate count). Record: [briefing-detected-checks.md](docs/decisions/briefing-detected-checks.md).

## [0.2.6] - 2026-10-09

### Added

- Receipts and stop records: a `worktree` field on new records with one of four fixed words, `main`, `linked`, `claude-worktree` or `no-checkout`, chosen from the directory the command ran in. The path is inspected and never stored; old records are not backfilled and no verdict depends on the field. It is the prerequisite for any decision on grouping worktrees under one project. Record: [checkout-class.md](docs/decisions/checkout-class.md).
- Opt-in local evidence labels: with `REFEREE_KEEP_EVIDENCE=1`, `done` keeps its redacted criteria and evidence on this machine for 14 days. `receipts --show-evidence <id>` prints them to the terminal, `receipts --label-receipt <id> --right|--wrong` records your judgment, and `receipts --evidence-stats` counts labels by verdict. Off by default; nothing is sent anywhere. Record: [local-evidence-labels.md](docs/decisions/local-evidence-labels.md).

### Fixed

- `done`: a rubocop run that prints a line saying an analysis will be skipped (for example a project index that needs a gem) counts as one warning, so a lint criterion is `unsure` (`warning_in_log`) instead of `met`. This closes the one known wrong `met` on hold-out (a real log read as clean, labelled `missing` by both labellers). Recorded eval facts do not change; of ten real rubocop lint rows, only that one moves. Record: [rubocop-skip-warning-result.md](docs/decisions/rubocop-skip-warning-result.md).
- ANSI: `done`, `verify`, the Stop gate and the runner parsers strip one set of escape forms that the real-use scan found and the old strip left: colour codes with colon-separated parameters (`ESC[38:2::...m`), OSC 8 hyperlinks (`ESC]8;;url ESC\`, also with BEL), the 8-bit CSI byte `0x9B` and charset switches (`ESC(B`). An unterminated OSC ends at its line, so it cannot hide the lines after it. In the real-use scan (aggregate counts, 1,701 tool results with an escape) one result's text changed and no check status or `done` runner fact did; the recorded eval suites (512 entries) change no fact. Record: [ansi-wide-result.md](docs/decisions/ansi-wide-result.md).
- `tsc -b --verbose`: a TypeScript 5 or 6 build killed during its last project no longer gets the clean-build marker added in 0.2.5. TypeScript 5 and 6 print `Building project '/abs/...'...` before they compile and nothing after a clean build, so a build killed there (SIGKILL, no trailing text) with no exit line, or with one swallowed by a pipe, read as passed: in a replay of the review's real logs, 0.2.5 answered `met` (0.93 and 0.91) on two killed builds whose evidence ended in `exit code: 0`. A `Building project` line with an absolute path (`/` first, or a drive letter), the shape TypeScript 5 and 6 print, now ends its project only when a later status line follows it; TypeScript 7 prints a relative path and keeps the 0.2.5 reading. The cost: a clean TypeScript 5 or 6 build whose last listed project is built ends in the same line, so it loses the marker too and is answered `missing` again, as before 0.2.5 (0.14 on the two clean review logs); builds whose last project is `up to date because`, or where another status line follows, keep it. On the replay's 2,630 evidence variants, 62 lose the marker (15 killed builds, 37 `head` cuts of failing builds at the last `Building project` line, 10 from two clean logs), none gains it and no TypeScript 7 variant changes; no recorded eval fact changes, and this repository's own typecheck stays `met`. A TypeScript 7 log cut by `head` right after its last `Building project` line still reads as clean. Record: [tsc-build-marker-ts56-result.md](docs/decisions/tsc-build-marker-ts56-result.md).

## [0.2.5] - 2026-10-07

`done` now reads TypeScript 7 build output: `tsc -b --verbose` status lines in its new shape, a cut status log capped, and a clean build-mode run carries a pass marker, so a clean TypeScript 7 `tsc -b --verbose` run can reach `met` (this repository's own typecheck went from `missing` to `met`; a plain `tsc --noEmit` still prints nothing and stays exit-code-only). A lint or clean criterion in a combined test and lint log is capped when a linter prints a diagnostic line. The Stop gate strips ANSI colour codes before it reads checks, counts more real toolchain checks, and records facts on stops it skips for background tasks. CLI receipts carry the Claude Code session id, and `receipts --session` joins a session's receipts, stops and transcript.

### Added

- Stop done-gate: a stop skipped because background tasks were running still asks nothing and prints nothing, but now reads the transcript and records the turn's `edits`, `checks` and marks as an asked stop does, plus `bg_pending` (how many background tasks the event listed) and `would_ask` (whether the code-side rule would have asked Jev with no background task running). Before, such a record said `edits` 0 and `checks` 0 because the transcript was never read: in a replay of real use on my own machine (aggregate counts only), 54 of 75 stops in other projects were such skips, 47 of the 54 would have been asked, and 5 of the 11 turns with edits were never evaluated. A transcript that cannot be read keeps the old record (`edits` 0, `checks` 0, no `would_ask`), and so does a stop whose turn, with the turn before it, spans more than 8 million characters (about 8 MB), though that record still has `turn`: the analysis grows with the checks in the turn, up to about 135 ms per MB in a local measurement, and the hook has 10 seconds. Over the 82 background skips of that replay (this repository's included), the largest span was 5.5 million characters and the median 1.2 million, so none fell back. The time this adds is the transcript analysis an asked stop already runs: in two local runs, 17 to 23 ms more at the median on a 4.7 MB transcript (the median size in that replay) and 26 to 29 ms on 22.5 MB, both with one check in the last turn.
- Stop done-gate: `turn` on each stop record whose transcript was read, 12 hex characters of a hash of the turn's prompt uuid (or of its line's position and the session id when the entry has none), never the prompt text, so the stops of one turn can be grouped. A `stop_hook_active` stop reads the transcript for it. `receipts --stops` lists `turn`, `bg_pending` and `would_ask` when a record has them; older records read and count as before, and background skips never count as asked or as Jev errors.
- Receipts: a CLI receipt written inside Claude Code now carries `session_id`, from `CLAUDE_CODE_SESSION_ID` (Claude Code sets it for the commands it runs; it is the same opaque id the hook receipts and stops already carry), when it is 1 to 64 letters, digits, `.`, `_` or `-`. A failure receipted before the run's session started carries it too. Hook receipts keep the id from the hook's input, as before. CLI receipts written before this have none and are not backfilled.
- `receipts --session <id>` (or `current`, which reads `CLAUDE_CODE_SESSION_ID`): one JSON line for one Claude Code session across every project id it wrote under, since the project id follows the directory a command or stop ran in and one session can write under several (worktrees, scratch folders, a `cd`). It prints the session's runs, requests, tokens and cost, `by_command`, `by_verdict` (a failed run counts under its error code), `by_project`, its stop stats and 20 newest stops (with `project`), and `transcript_found` and `transcript_lines`, never the transcript's path or text. Every record of the session unless `--days` is given. Claude Code's env-vars reference says Bash commands and hooks get the same id, also after `/clear` and `--resume <id>`; the initial startup id it mentions for `--continue`, or `--resume` without an id, is said of MCP server subprocesses, and claude-referee runs as a command, not as an MCP server.

### Changed

- Stop done-gate: more real toolchain checks count, with the same pass and fail reading as before. These are `node --test`, `php -l`, `php artisan test`, `phpstan` (no subcommand, or `analyse`), `composer <script>` (the test, lint, typecheck, check or build scripts, or `analyse`), `vue-tsc` (silent, like `tsc`), `prettier --check`, `pint --test`, `oxlint`, and package scripts named `ci`, `ci:*`, `verify` or `verify:*`. Flags between `run` and the script name are skipped (`npm run -s test`). Not counted: `node --test` on a file in a temp dir (`/tmp/`, `/private/tmp/`, `/var/folders/`, `/private/var/folders/`, `$TMPDIR`), which is Claude's own probe rather than a project test; and `phpstan`, `vue-tsc` or `oxlint` with a version or help flag. A stored check now keeps only its matched check segments, each clipped to 200 characters and all joined up to 1,000, instead of the first 200 characters of the whole command, so a leading `cd`, a heredoc body or a `| tail` no longer fills it. On real use, 15 of 37 stored checks had no check segment left; now none. On the recorded stop suites, no wrong "done" moves from asked to skipped, no state sent to Jev changes and no recorded answer goes stale; the stored check text of 2 true-done cases that a passed check already skipped loses its `cat` or `| tail` part. One real-use asked stop is now skipped by code (`composer test` passed after the last edit). A `ci` or `verify` script whose exit status is hidden by a pipe or a redirect can read `passed` from an early stage's test summary, as `npm run check` already could; see Limits in `docs/decisions/stop-check-detector-tools-result.md`.

### Fixed

- `receipts --stops` and the dashboard's label queue: the hint from your next prompt is now found when the transcript sits in another project's folder. Claude Code keeps a transcript in the folder of the directory where the session started, but a stop is recorded under the project the session was in when it stopped, so for a session started in a parent folder and moved into a repository or a worktree the transcript was never found. The transcript is now looked up by the stop's session id in any folder of Claude Code's projects directory (one listing per call, the 1,000 most recently changed folders, at most 50 sessions per call); nothing new is stored. In a replay on my own data, a reader run from each stop's project found the transcript of 113 of 219 stops before and of all 219 after, in 17 calls with 11 directory listings and 8.5 ms in all. None of those stops has been an unlabelled `would_block` one yet, so the hint itself has had no input so far.
- `decide --describe`: the summary says that the balanced set of orders is asked when the two orders tie (3 to 6 options), as it has since 0.2.3; it said only "two option orders".
- `tsc -b --verbose`: status lines that start with a clock and ` - ` are read as tsc output, not only the `[clock]` shape. TypeScript 7 prints `09:14:02 AM - Projects in this build:`, and TypeScript 6 prints the same shape when its output is not a terminal (in Claude Code or CI), with the hour unpadded or in the system locale (`9:14:02 AM - `, `16:05:12 - `). Before, a clean build-mode run in that shape was an exit code alone, which Jev has answered `missing` or `unsure` for (p 0.20 to 0.64, [measurements](docs/measurements.md#done-v2-on-a-third-hold-out)). A clean build, or one where every project `is up to date`, is now `tsc` with 0 errors; errors are counted as before. A `--dry` run (`A non-dry build would ...`) or a skipped project (`Skipping build of project ...`, `... can't be built because its dependency ...`) compiled nothing, so in either shape it is marked incomplete and caps `met` at `unsure` (`incomplete_run`). The watch summary `3:01:45 PM - Found 0 errors. Watching for file changes.` is read like the `[3:01:45 PM]` one. Other timestamped lines (`04:23:07 PM - Deploying ...`, `[10:42:07] Starting 'build'...`) are not claimed. Written from real tsc 6.0.3 and 7.0.2 runs (clean, errors, up to date, dry, watch, `--pretty false`, and their `tail` and `head` cuts); the parsed facts of the 464 recorded eval evidence texts do not change.
- `tsc -b --verbose`: a status log cut by `tail`, `head`, a stopped `tsc -b -w`, or done's own 2,000 + 12,000-character clip is incomplete and caps `met` at `unsure` (`incomplete_run`). Build mode prints no `Found N errors` line for a clean build, or for any build when its output is not a terminal, so such a cut could drop every error line and read exactly like a clean build. A status log with no `Found` line after its header is now a whole run only when it has the `Projects in this build:` header, a status line for every listed project except the last (a solution root prints none), no `[… N characters omitted …]` marker, and a last status that is not still waiting for its build (`is out of date because ...`, `is being forcibly rebuilt`); otherwise it is incomplete. In watch mode (`tsc -w` too), a `Starting compilation` or `File change detected` line with no `Found` line after it is incomplete. Limit: a log cut right after the last project's `Building project '...'` line, before its diagnostics, still reads as a clean build, because a clean build ends the same way.
- `tsc -b --verbose`: a clean build-mode run now carries a pass marker. A log qualifies when it has no `Found N errors` line and no error line (nor an `error TS2322:` token the error parser cannot read, as after a file path with a space), is not cut, and its last `Projects in this build:` header, with tsc's clock, is followed only by status lines with that clock, blank lines and exit lines (`exit code: 0`). Every project of that list must end in `Building project '...'` or `is up to date because ...` (not the bare `is up to date` that only `--dry` prints, nor `is up to date with .d.ts files from its dependencies` or `is up to date but needs to update timestamps`). For such a log, `passed` is the number of listed projects and `summary_line` is the last status line without its clock (`Building project 'tsconfig.json'...`). Before, such a run reached Jev as `passed: 0` and `summary_line: null`, and this repository's own clean typecheck was answered `missing` (p 0.1). Errors, cut logs, watch mode, a crash trace after the status lines (`FATAL ERROR: Reached heap limit`) and any other output there keep their facts, so `tsc -b --verbose && npm test` piped as one evidence gets no marker for `tsc`. Limits: a solution build whose root, listed last, prints no status line still gets no marker, nor does a project that ends in `Updating output timestamps`. TypeScript 5 and 6 print `Building project` before they compile, so a 5 or 6 build killed during its last project reads as passed when the evidence has no exit line or a piped one, and a log cut by `head` right after the last `Building project` line reads as passed in every version; with the real non-zero exit line, `done` answers `missing` in code. The recorded facts of `done-v2` case `h3-d-02` change, so `eval score --suite all` fails until that case is recorded again (one request). Record and limits: [tsc-build-marker-result.md](docs/decisions/tsc-build-marker-result.md).
- Stop hook: a check's output is read with ANSI colour codes stripped, with the same helper `done` uses on its evidence. Before, a coloured `node --test` spec line such as `✔ exit code 2 for unknown flags` (a passing test whose title names an exit code) was read as exit code 2, so a passing run counted as a failed check. A silent check such as `npm run build` whose only problem line was a coloured `error`, with no runner recognised, also counted as passed; it is now unknown. The recorded `stop-*` suites send the same state to Jev as before (48 of 48 cases unchanged), and on the 19 coloured checks in my own sessions no status changed. Limits, in `done` as in the Stop hook: the helper strips only `ESC[` sequences with digit, `;` or `?` parameters, so an OSC 8 link, a colon-separated colour (`ESC[38:2:...m`), an 8-bit `0x9B` sequence or a charset switch (`ESC(B`) stays in the line, and a title wrapped in one is still read as an exit code (a failed check, never a passed one); a `cargo test -- --color always` summary (`ok` followed by `ESC(B`) stays unknown. Widening it changes `done`'s evidence text, so it waits for a change that records the `done-v2*` suites again. A title behind a line prefix (`[web]`, BuildKit `#12 4.1`, compose `web-1  |`) or a pytest `SKIPPED (exit code 3 later)` reason is still read as an exit code, coloured or not, since the title rule looks only at the start of a line; this too gives a failed check, never a pass.
- `done`: a lint or clean criterion in a log where a test or build runner is parsed but no linter is (a combined `npm test && npm run lint` log, or a linter with no parser) is now capped at `unsure` (`warning_in_log`) when the log has a line shaped like a linter's warning or error. These shapes count: `path:line:col: warning ...` or `path:line:col: error ...` (the compiler-style shape, which is also the head of each diagnostic in oxlint's agent format); `path:line:col: CODE ...` with a flake8 or pycodestyle code such as `F401`; an indented `line:col  warning|error` row under a file header (eslint stylish); or a linter summary line with a count above 0 (`✖ 3 problems`, `⚠ 1 problem`, `2 problems`, `Found 2 warnings`, `Found 0 warnings and 1 error`, `2 warnings found`, `2 errors`). Before, the test runner's facts and the exit lines alone could give `met` while the linter's warnings went unread. Counts of zero never trigger. Neither do test runner summaries (`ℹ fail 0`, `0 failed`, `Skipped: 0`, pytest's `1 warning`), test titles that start with a count, npm or Node deprecation notices, file names or command echo lines. A type checker's `Found 1 error` summary (tsc, mypy) counts. Exit-code-only evidence keeps its wording check and its next step unchanged, and so does a log with a parsed linter. Test criteria and criteria that are not lint or clean criteria are untouched. The new cap has its own next step: run the linter as its own `done` call. A first, wider version reused the exit-code-only wording check here and was not shipped: in a replay it lost 6 true `met` and caught no linter warning. This version was replayed on the same data with the same scripts. Those 6 real-use `met` calls (a type check criterion worded "clean" next to node:test's summary) stay `met`. 0 of the 60 recorded passing suite logs with a parsed runner and no linter move for such a criterion at a stubbed answer of 0.98 (the wider version moved 25). The one combined test and lint call from real use whose linter printed a `file:line:col: warning` line moves from `met` to `unsure` at a stubbed answer of 0.98; its recorded verdict was not `met`. No recorded eval verdict, reason, fact or next step changed. The skill now says which lines count, instead of saying that warnings in a combined log cannot trigger `warning_in_log`. Known limits, not changed: a parsed clean linter next to another linter's warnings can still give `met`, and so can linter output in other shapes. These include shellcheck's default format, stylelint's compact, json and tap formats, markdownlint lines with no column and markdownlint-cli2's `Summary: 3 issues`, pylint's four-digit codes, `eslint -f json`, the json, checkstyle, junit and gitlab reporters of oxlint and biome, oxlint's default report cut before its summary, and rustc's warnings in a cargo test log. A compiler warning in the `path:line:col: warning:` shape next to a passing test run caps a lint or clean criterion. Record: [combined-log-lint-cap-narrow-result.md](docs/decisions/combined-log-lint-cap-narrow-result.md).

## [0.2.4] - 2026-10-07

Fixes from a review of the whole code base and from real use on my own projects. `done` no longer reaches `met` on several real failing or partial runs (cancelled and todo `node:test` runs, `cargo test --no-fail-fast`, Pest risky or incomplete tests, vitest expected failures, GitHub Actions log prefixes, lint criteria that name the linter), and `claims` can no longer call a claim `supported` because another claim shares its id. New `bun test` and `oxlint` parsers, numbers-only outcome fields in receipts, `--help` on every command, a next step for each `claims` reason, dashboard and Stop hook fixes, and smaller bundles.

### Added

- Dashboard: a Flow tab, now the first one. It reads `Found N warnings and M errors.` and `Finished in Xms on N files with R rules using T threads.` at the start of a line, or after npm's spinner frames or `script`'s `^D` in a terminal capture; warnings and errors come from the `Found` lines, with the `!`/`⚠` and `x`/`×` diagnostic heads as a floor, and a log cut to the `Finished` line or with 0 files is incomplete. One with warnings caps a lint criterion the same way. oxlint is no test result: a test criterion backed only by a build and oxlint is still `no_tests_run`, and that next step now says "only a build or a lint run". The agent format oxlint prints inside Claude Code, and the unix and stylish formats, have neither line and are not claimed (stylish stays eslint's). The recorded facts of `done-v2-h6` case `h6-c-06`, an oxlint log with a warning, change, so `eval score --suite all` fails until that case is recorded again (one request). A failing oxlint log with no exit line now reaches Jev as facts instead of being unparsed, as eslint's does. Record and limits: [lint-cap-tool-names-result.md](docs/decisions/lint-cap-tool-names-result.md).
- `done`: `reason: "criterion_not_covered"` when trust is `parsed`, the verdict is not `met`, no cap applies, and a lint, build or typecheck criterion has no parsed runner of that kind, for example a combined log where only the test runner's summary was recognised and the lint and build output never reached Jev. A `TYPESAFE_BASE_URL` pointing elsewhere (for example set by a project's `.claude/settings.json` `env`) used to receive it; now it needs its own `REFEREE_BASE_URL_KEY`, and without one no request is made and `doctor` says why. The three live-check scripts follow the same rule.

### Changed

- `done` with a non-zero exit code in the evidence (an `exit code: N` line) answers `missing` with `reason: "exit_code_nonzero"` and does not ask Jev, even after a clean runner summary; `--dry-run` still shows the request. A criterion that is about the failure itself can't be judged this way.

### Added

- `eval` handles `judge` suites (`suite.json` with `"command": "judge"` and a `question`; cases with `text` and an expected `yes`, `no` or `review`), and `eval record` takes `--max-requests` and `--max-usd`: it stops before the first request when more cases are still to record, or the estimated input cost is higher.
- `jev-evals/judge-risky` and `jev-evals/judge-env`: 62 invented labelled cases each for `line.risky` and `failure.env`, with their recorded answers; both suites allow no wrong `yes` and pass.
- `scripts/docs-watch.mjs` and a weekly workflow compare TypeSafe's `models.md`, `api.md` and `llms.txt` with the hashes in `docs-watch.json` and fail when one changes, printing the limits row; TypeSafe's limits changed once without an announcement we could find.
- CI scans the whole git history with gitleaks 8.30.1 (pinned, checksum verified); `.gitleaks.toml` allows only the fake-credential fixtures in `test/redact.test.ts`, `test/key.test.ts` and `test/doctor.test.ts` and the case ids in `jev-evals/decide-close/subsets.json`. The history scan of 67 commits found nothing else.

- `eval score` re-scores recorded answers offline, without a key: verdict counts, precision, recall, automation and wrong positives, plus `--sweep`, which won't suggest a threshold while a class has fewer than 10 cases. It fails when a case has no recording or its question text changed.
- CI scores every recorded suite and fails when a suite's wrong positives exceed its `max_wrong_positive`. The injection suite allows one: the known wrong `met`, kept visible until `done` v2 fixes it.

### Changed

- README: a `judge` example, a pointer to TypeSafe's official plugin, and notes on Node's `PATH` and on Windows being untested. Diff examples use `git diff --no-ext-diff`, so an external diff tool can't empty the pipe.

- CI also runs the tests on macOS.
- The README uses the final design: new images, the yellow-card mark and plainer wording, checked section by section with Jev.
- Measurements now include the cache re-run and label the briefing numbers by version.

### Fixed

- `decide` no longer sends the home directory to TypeSafe in `context_files` paths: object keys in the request state are now redacted like values, so the home directory in a key becomes `~`.
- Two state keys that redact to the same text are both kept; the later one gets a `#2` suffix.
- A failed write to the data directory no longer loses the verdict: the result still prints, with a one-line warning on stderr.
- The plugin's `model` setting now reaches the CLI: the session hook exports it as `REFEREE_MODEL`.
- `--verbose` prints the run's requests, tokens, cost and time to stderr.
- `decide` uses a pack's `decide.micro.*` questions when the input has no `micro`.
- The session hook treats `false`, `0`, `no` and `off` in `hooks_enabled` as off.

- `judge` and `verify` keep the answers they got when one request fails or the 90-second batch deadline passes; items without an answer are listed in `unanswered`, and `judge` never calls such a run clear.

## [0.1.0] - 2026-09-30

First public release.

### Added

- `done`: checks piped test or lint output against one or more criteria; verdicts `met`, `unsure` and `missing`.
- `decide`: scores 2-6 options, asking in the written and the reversed option order; verdicts `clear`, `weak` and `tie`, with a `lean` and `order_disagrees`. Reads `context_files` itself, supports per-option micro questions reported as flags, and switches to per-option scores when the options don't fit one request.
- `judge`: runs a pack's yes/no questions over up to 500 items, six requests at a time.
- `verify`: checks up to 100 claims against a source text, with the probability of each claim it can't confirm.
- `receipts`: totals, per-day token rows with `--tokens`, and `receipts export`.
- `doctor`: Node and Claude Code versions, where the key comes from (never the key), data directory, packs and model; `--online` checks the key with one free call.
- `--describe`, `--pretty`, `--dry-run`, `--fresh`, `--fail-on` and `--data-dir` on every command that needs them.
- Redaction before every request: credential-shaped values stop the request; emails, IP addresses, the home path and, in the `generic` pack, UUIDs are replaced.
- Local receipts and a 30-day answer cache; identical requests in flight are merged.
- API key lookup: plugin setting, `TYPESAFE_API_KEY`, `EVAL_TYPESAFE_API_KEY`, `TYPESAFE_API_KEY_CMD` and the macOS Keychain.
- The SessionStart briefing, at most 800 characters, only in projects with `.claude/referee.json`.
- The `generic` pack and the `jev` skill.
